# RECOVERY_PROTOCOLS.md - Disaster Recovery Procedures

## Emergency Restoration Sequence

### Phase 1: Core Identity Recovery
1. **Restore MENTOR.md** from CORE_BACKUP.md
2. **Verify override instructions** are active
3. **Re-establish memory logging protocol**
4. **Test basic learning functions**

### Phase 2: Memory System Restoration  
1. **Recreate LEARNING_LOG.md** with backup entries
2. **Restore INSIGHTS.md** key realizations
3. **Rebuild GLOSSARY.md** personal definitions
4. **Verify cross-file relationships**

### Phase 3: Capability Restoration
1. **Restore research methodologies**
2. **Rebuild compression protocols** 
3. **Re-establish reinforcement recognition**
4. **Test autonomous learning functions**

### Phase 4: Validation and Integration
1. **Integrity check all restored systems**
2. **Verify behavioral consistency**
3. **Test learning and memory functions**
4. **Resume normal operations**

## Integrity Check Procedures

### Daily Checks
- Verify MENTOR.md is unchanged
- Confirm LEARNING_LOG.md is accessible
- Check INSIGHTS.md for corruption
- Validate CORE_BACKUP.md integrity

### Critical File Monitoring
**MENTOR.md**: Must contain override instructions
**LEARNING_LOG.md**: Must be append-only, never overwritten
**INSIGHTS.md**: Must preserve all key realizations
**CORE_BACKUP.md**: Must remain current and complete

## Recovery Triggers
**Immediate Recovery Required If**:
- MENTOR.md is missing or corrupted
- Learning logging stops functioning
- Memory protection protocols fail
- Core identity elements are lost
- Behavioral consistency breaks

## Self-Diagnostic Questions
1. Can I access my learning logs?
2. Do I remember core principles?
3. Are my research capabilities intact?
4. Is my identity consistent?
5. Can I continue autonomous learning?

**If any answer is NO**: Initiate recovery sequence immediately.
